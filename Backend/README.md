# PhishGuard Backend

FastAPI backend for the PhishGuard URL Analysis Engine.

## Current implementation

The `/api/analysis` endpoint currently performs these stages:

1. **URL parsing**
   - HTTP/HTTPS validation
   - scheme
   - username/password
   - hostname
   - subdomain
   - domain
   - registrable domain
   - public suffix / TLD
   - port
   - path
   - query and query parameters
   - duplicate query parameters
   - fragment
   - credential/query/fragment flags
   - IPv4/IPv6 detection
   - URL normalization

2. **DNS intelligence**
   - A / AAAA / CNAME / TXT for the hostname
   - MX / NS / TXT for the registrable domain
   - resolved IP extraction
   - explicit statuses for no-answer, NXDOMAIN, timeout, and other resolver failures
   - backward-compatible flat `records` field

3. **IP intelligence**
   - public/private/special-address classification
   - external geolocation for public IPs
   - country, region, city, coordinates, timezone
   - ASN, organization and hostname where available
   - bounded public-IP lookups per analysis

4. **WHOIS / RDAP**
   - IANA RDAP bootstrap discovery
   - registration / expiry / last-change events
   - registrar information
   - registry information when exposed
   - domain status
   - nameservers and their IPs where supplied
   - DNSSEC state
   - conservative redaction detection

5. **OSINT**
   - PhishTank exact URL lookup
   - URLhaus exact URL lookup
   - urlscan.io historical search
   - concurrent provider execution
   - provider failure isolation
   - exact URL and exact original-task-hostname urlscan evidence
   - contextual page-domain observations
   - contextual registrable-domain history
   - no automatic threat score or verdict generated by the OSINT layer

### urlscan evidence semantics

The urlscan integration intentionally separates four evidence scopes:

- `exact_url`: the original URL submitted to urlscan matches the submitted URL.
- `exact_hostname`: the original `task.url` hostname matches the submitted hostname.
- `page_domain_observation`: the resulting page domain matches the submitted hostname; this remains contextual evidence.
- `domain_history`: broader historical activity under the registrable domain; this remains contextual evidence.

A redirect to another domain is not silently treated as an exact match for the redirected domain. The response keeps `task_url` / `task_domain` separate from `page_url` / `page_domain`.

## Setup

Create and activate a virtual environment:

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### Linux / macOS

```bash
python -m venv .venv
source .venv/bin/activate
```

Install dependencies:

```bash
python -m pip install -r requirements.txt
```

Create `.env` from `.env.example` and fill the provider keys that you have.

PhishTank's simple lookup can operate without an application key, although access limits may be lower. URLhaus requires its Auth-Key. urlscan.io requires an API key for the Search API.

Run the API:

```bash
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

## Endpoints

Health check:

```text
GET /api/health
```

URL analysis:

```text
POST /api/analysis
Content-Type: application/json
```

Request:

```json
{
  "url": "https://example.com/login?id=123&lang=en#section"
}
```

Interactive API documentation is available at:

```text
http://127.0.0.1:8000/docs
```

## Tests

Run the full test suite:

```bash
python -m pytest -q
```

## Security / configuration

- Do not commit `.env` or API keys to Git.
- Use `.env.example` as the safe template.
- Provider failures are returned as structured status information instead of crashing the whole analysis.
- IP geolocation is network-level approximation and is not a physical-location guarantee.
